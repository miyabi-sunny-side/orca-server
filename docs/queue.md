# 印刷キュー

保存したプレートをプリンターごとに並べ、空のビルドプレートを確認して1件ずつ印刷します。
キューはSQLiteに保存され、サーバー再起動後も残ります。完了や再起動だけで次を自動開始しません。
[プリンター](printer.md)と[材料・AMS](filaments.md)を登録してから操作してください。

## 画面から操作する

1. プレートの作成・編集で、要求機種/ノズル・フィラメント・工程・ビルドプレートを保存します。
2. 詳細の「印刷キューへ」を押します。対応する実機が複数あるときだけ追加先を選びます。
3. キューの「前へ」「後へ」「削除」で待機順を整理します。条件は「プレートの条件を編集」から変更します。
4. 造形物を取り外し、空のビルドプレートを戻して確認欄をチェックし、「次を印刷」を押します。
5. 完了後も取り外しを確認して次を始めます。最後は「取り外しを完了」で閉じます。

追加時は条件不足・機種/ノズルの不一致・指定材料の未装填・未同期を拒否し、理由を表示します。
印刷中でも後続の追加はできます。追加だけでは印刷を開始しません。
AMSは[同一材料の使用順](filaments.md)で自動選択し、追加後も準備開始時に装填を照合します。
材料がなくなった場合は待機のまま保留します。プレート編集・機器登録・AMS設定から理由を解消してください。

準備を開始すると、プレート構成・個数・最新STL・同梱Orcaプロファイル・材料の温度設定を固定します。
配置・スライス後、同じ印刷データを転送します。準備後の編集はその実行へ反映しません。
準備中にAMSの割当や材料の識別情報が変わった場合も開始を止めます。

## 失敗・再起動からの復旧

「確認が必要です」では表示された理由と本体を確認してください。印刷が続いていれば再実行せず、報告の復帰を待ちます。
再起動時は保存した試行と機器の報告を照合し、印刷中・取り外し待ちを復元します。
準備中や開始結果不明の試行は要確認とし、命令を自動再送しません。機器が待機を報告しただけでは「未印刷」と判断しません。
DBをバックアップから戻した場合も同じです。

再実行には、同期済みの待機状態と本体・空プレートの確認が必要です。
「同じプレートを再印刷」は前の試行の構成・印刷設定を保ち、新しい試行を準備します。
取得済みのSTLが残っていれば再利用し、取得前に失敗したSCAD参照は再取得します。
条件を変えて印刷する場合は現在のジョブを除き、プレートを編集して新しく追加します。
不要なら「現在のジョブを除く」で閉じます。これらは本体の印刷停止命令ではありません。
完了・取消済みジョブは通常表示から除き、実行ファイルとDB行を片付けます。恒久的な印刷履歴は保持しません。

送信結果が不明なら「同じ要求を再確認」で確認します。別画面と競合した場合は「最新状態を読み直す」で対象を確認し直します。
古い確認欄や別ジョブへの自動再送を使って次の印刷へ進むことはありません。

## APIの対象と応答

以下は外部クライアントや近傍ボタンを接続する人向けです。
`GET /api/printers`で対象IDを取得し、`GET/POST /api/queue?printer_id=PRINTER_ID`を使います。
1台だけならIDを省略できます。複数台での省略は409、不明なIDは404です。

| 項目 | 内容 |
| --- | --- |
| `epoch` | サーバー再起動・機器設定変更を識別する値。 |
| `generation` | キュー操作や進行状態の更新で変わる整数。 |
| `request_id` | この応答を基にした操作に使えるUUID。 |
| `waiting` | 待機ジョブ。先頭が次の対象。最大100件。`hold_reason`があれば保留。 |
| `current` | 準備中以降のジョブ。なければ`null`。 |
| `allowed` | 確認後に行える`next`・`retry`・`discard`。POSTでも再検証します。 |
| `admission` | `plate_id`をqueryへ追加した場合の`plate_version`・`allowed`・`reason`。指定がなければ`null`。 |
| `printer` | [機器状態](printer.md#状態api)。 |

ジョブは`id`、`plate_id`、`name`、`state`と、材料・要求機種・工程・ベッド・解決したAMSを持ちます。
試行の情報は`attempt_id`、`artifact_path`、`last_error`です。
待機分はプレートの最新条件と`plate_version`を返し、未設定や解決できないAMSは`null`です。
`current`は確定済み条件を返します。`actual_ams_slot`は同期した印刷中の実使用slot（0〜15）で、未確認なら`null`です。
標準Auto Refillで使用slotが変わっても要求材料・開始時slot・job/attempt IDは変えず、新規開始もしません。
実行ID・ファイルパス・エラーは未設定なら`null`です。`artifact_path`はサーバー内の実行ファイルで、ダウンロードURLではありません。
同じプレートを複数追加すると別々のジョブIDになります。

| `state` | 意味 |
| --- | --- |
| `queued` | 待機。材料・ノズル等の不一致もこの状態で編集可能。 |
| `preparing` | 最新モデル取得・配置・スライス・転送・開始確認。受理応答だけでは印刷中にしません。 |
| `printing` | 対象の印刷開始を確認。 |
| `awaiting_removal` | 完了を確認。造形物の取り外し待ち。 |
| `needs_attention` | 失敗・停止・通信断・不明な開始結果。本体の確認が必要。 |

## プレートを追加する

すべての操作は、直前に取得した`epoch`・`generation`・`request_id`と`action`をJSONでPOSTします。
次の例のIDと世代は応答の値に置き換えます。

```json
{
  "epoch": "取得したepoch",
  "generation": 0,
  "request_id": "取得したUUID",
  "action": {
    "type": "add",
    "plate_id": "プレートID",
    "plate_version": 1
  }
}
```

追加前に`GET /api/queue?printer_id=PRINTER_ID&plate_id=PLATE_ID`を読み、`admission.allowed`と理由を確認します。
`admission.plate_version`が表示したプレートの版と一致することも確認してください。
POSTでも現在のプレート版・登録実機・AMSを再照合します。条件やslotはPOSTで上書きできません。
待機条件の個別編集APIはありません。[プレートAPI](plates.md#印刷条件を保存する)で編集します。

| `action.type` | 追加項目と操作 |
| --- | --- |
| `add` | `plate_id`、`plate_version`。末尾へ追加。 |
| `move` | `job_id`、`index`。待機中の位置を0始まりで指定。 |
| `remove` | `job_id`。待機を取消。 |
| `next` | `expected_job`、`removed_job`、`cleared:true`。先頭1件を準備開始。 |
| `retry` | `expected_job`、`cleared:true`。要確認ジョブを再準備。 |
| `discard` | `expected_job`、`cleared:true`。要確認・取り外し待ちを閉じる。 |

## 次の印刷と再送

`next`の`expected_job`は取得した`waiting[0].id`、`removed_job`は取り外した`current.id`です。
最初の印刷では`removed_job: null`とします。`retry`・`discard`の対象は`current.id`です。
操作前に人が造形物と空のプレートを確認し、取得した対象のまま要求を保存して1回送ります。

```json
{
  "epoch": "取得したepoch",
  "generation": 1,
  "request_id": "操作のUUID",
  "action": {"type":"next","expected_job":"先頭ジョブID","removed_job":null,"cleared":true}
}
```

応答が届かなければ同じ要求を再送できます。直前の受理要求と完全一致する場合、操作を繰り返さず現在状態を返します。
同じIDで内容を変えた要求、古い世代、再起動前のepoch、別の取り外し対象は409です。
409時は新しい先頭IDへ自動で差し替えず、人が対象を確認してから操作し直してください。
近傍ボタンも、この取得・確認・保存した要求の送信を1回の押下として扱います。

成功は200と状態を返します。200は印刷完了を示しません。`current.state`と`printer.start`で経過を確認します。
入力不正は400または422、未知の対象は404、競合は409、別Originからの変更は403です。
