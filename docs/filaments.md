# フィラメントとAMSの材料管理

製品の共通設定と色を分けてSQLiteに保存し、AMSの各スロットには色を対応づけます。
初期状態の台帳は空です。スプールの在庫は管理しません。

## 製品と色を登録する

1. メニューの「フィラメント」→「製品を追加」で、製品名・メーカー・材料種別を保存します。
2. 純正Bambu材料を自動識別する場合は「自動識別の詳細」に材料IDも入力します。PLA MatteのIDは`GFA01`です。
3. 製品の「色を追加」で基本色、色名、色見本を選んで保存します。黒・白・黄を追加しても共通情報の再入力は不要です。
4. 製品の「設定を追加」で機種・ノズル径と基本プロファイルを指定します。この設定と温度調整は全色に反映されます。

色行から色名・色見本を編集できます。「正確な色を編集」では8桁のRRGGBBAAを指定します。
黒の`000000FF`とチャコールの`161616FF`は異なる色です。末尾`FF`は不透明を表します。
自動対応には正確な色を使い、黒という名前だけでは同一視しません。
PETGとPETG-GFも区別します。同じID・種別・色の候補が複数あれば、自動で一つを選びません。

既存の白黒が別々に登録されている場合は、残す製品で「既存の色をまとめる」を開いて対象を選びます。
メーカー・材料種別・Bambu ID・全機種の設定が一致する場合だけまとめられます。名前から製品を推測しません。
材料ID・色・AMSの対応・待機ジョブは保持します。印刷準備中から取り外し待ち、要確認の色は終了後に操作してください。
個別調整が異なる登録は別製品として保持できます。共通化すると、その後の設定変更は全色へ反映されます。

## 機種別の温度設定

基本プロファイルは、同梱OrcaSlicer 2.4.2でその機種・ノズル径に対応するものから選択します。
初層と通常層のノズル温度・ベッド温度は個別に上書きでき、空欄なら基本値を使います。
ベッド温度を指定すると、選択したプレートの種類にかかわらずその温度を使います。0℃は加熱なしです。
同じ製品・機種構成の設定は一つで、全色と同じ構成の複数プリンターで共有します。
設定を変更しても、AMSが報告する温度範囲や材料名は書き換えません。

入力範囲はノズル120〜350℃、ベッド0〜120℃の整数です。これはアプリの入力制限で、機器がその全範囲に対応する保証ではありません。
材料メーカーの推奨温度と機器の上限を確認してください。
繊維入り材料は同種の樹脂の基本プロファイルも選べます。
0.2mm用の設定がなければ、0.4mm用の設定を流用しません。

印刷準備を開始すると、台帳の基本プロファイルと温度の上書きを固定してスライスへ適用します。
設定変更は次の準備から反映します。既に印刷中のデータは変更しません。
[スライスの設定](slicing.md)を参照してください。

## AMSに対応づける

「プリンター」一覧の「AMSの材料」を開きます。プリンター内のAMS IDとスロット番号ごとに表示します。
画面のスロット番号は1始まり、APIの`slot_index`は0始まりです。

- 自動対応: 装填・タグ・材料ID・種別・色が分かり、台帳の候補が一つの場合です。
- 手動対応: 材料名を押し、製品・メーカー・材質・色から検索して候補を選びます。
- 対応解除: 候補の「指定を解除」を選びます。同じ報告値のままなら、自動対応へ戻しません。

タグや報告値の変更、抜去を確認すると、それまでの対応を見直します。
残量だけが変わった場合は、手動対応を維持します。
タグのない材料を同じ報告値の別製品へ交換した場合は自動判別できないため、材料を指定し直してください。
編集中に観測内容が変わった場合は、画面を更新して選び直します。

各行の「+」で開く詳細には銘柄、色、材料ID、タグ、残量、温度範囲、自動識別設定を表示します。
残量`-1`などの未知値を0%として扱いません。起動直後・通信断・古い情報は「未確認」と表示し、
完全な状態報告を受け取るまで新しい材料の指定を受け付けません。古い対応の解除は可能です。
「状態を更新」はサーバーが受信した情報を読み直す操作で、RFID再読取・送り・加熱は起動しません。

### 同一材料の使用順と自動補充

同じ製品・正確な色で、この機種の共通設定を使えるスロットが複数ある場合は、詳細の「印刷開始時の使用順」で並べ替えられます。
既定は先に装填を観測したものからです。更新や再起動で順序は変わりません。抜去後の再装填や識別情報の変更は後ろに置きます。
移行前の順序が分からない場合はAMS/スロット番号順から始めます。時刻や残量から装填日時は推定しません。
タグなしの未観測交換は識別できません。先に使うスプールを変えたい場合は、使用順を手動で変更してください。

印刷中の材料切れにはプリンター標準のFilament Backupを使います。「自動補充」を開くと、
機器が報告した対応状況と有効状態を確認できます。対応が確認できた機器では有効・無効を変更できます。
「設定を送信しました」は反映の確認ではありません。通信断や反映待ちでは設定を送信し直さず、報告を確認してください。
開始時の使用順は機器の補充順を指定しません。補充の全順序を指定する機能はありません。

登録上同じ材料でも、機器側で異なる材料設定になっている場合があります。各スロットの「機器が認識する補充先」を確認してください。
登録上は同一と確認できない補充先には注意文を表示します。未報告の場合はプリンターまたはBambu Studioで確認します。
アプリは材料切れから新しい印刷を作ったり、別色・別製品へ独自に切り替えたりしません。

通信契約は[Bambu Studioの公式実装](https://github.com/bambulab/BambuStudio/blob/77b9dd94d1e3c432d5e74a18ab8de146ccf3b7c7/src/slic3r/GUI/DeviceManager.cpp)に合わせています。
設定要求は`print_option.auto_switch_filament`です。対応状況は`support_filament_backup`、有効状態は`home_flag`のbit10で読みます。
補充グループは`filam_bak`から取得します。
補充グループの表示は従来AMSのスロット0〜15を対象とします。フィールドがない場合は非対応と決めつけず未報告と表示します。
実際の材料切れからの継続可否は、機器・ファームウェア・機器側の材料設定に依存します。

装着したノズルの径・材質はプリンター設定に記録します。材料名・繊維の有無・プロファイルの要求硬度から
ノズルの対応可否は推定しません。使用するノズルと材料の組み合わせは、各メーカーの仕様で確認してください。
プレートが要求する機種・ノズル径と登録値の一致、機器が報告するノズルとの一致は、印刷準備時に確認します。

AMSや印刷ジョブから参照される材料は削除できません。先に対応を解除し、ジョブを終了・取消します。
色の削除は製品の共通設定を残します。製品の削除は全色・設定を削除し、参照があれば全体を拒否します。
ジョブから参照される機種別設定の削除・機種キーの変更も拒否します。

## API

JSONを送る操作には`Content-Type: application/json`を付けます。IDは各APIの応答から取得します。

| URL | 操作 |
| --- | --- |
| `/api/filament-products` | GET: 製品一覧（各製品の`colors`と`settings`を含む）。POST: 製品作成、201。 |
| `/api/filament-products/{id}` | GET: 製品詳細。PUT: 共通情報の更新。DELETE: 全色・設定を含め削除、204。 |
| `/api/filament-products/{id}/colors` | POST: 色の作成、201と`id`・`name`・`color`。 |
| `/api/filament-products/{id}/colors/{color_id}` | PUT: 色の更新。DELETE: 色の削除、204。 |
| `/api/filament-products/{id}/adopt` | POST: `{"filament_id":"既存の色ID"}`で共通設定が一致する色をまとめる、204。同じ所属への再実行も204。 |
| `/api/filament-products/{id}/profiles?machine=...` | GET: URLエンコードした機種キーに対応する基本プロファイルと温度。 |
| `/api/filament-products/{id}/settings` | POST: 全色に共通の機種別設定を作成、201。 |
| `/api/filament-products/{id}/settings/{setting_id}` | PUT: 共通設定を更新。DELETE: 削除、204。 |
| `/api/filaments?q=...` | GET: 色別材料一覧。任意の`q`で製品・メーカー・材質・色をファジー検索。 |
| `/api/filaments/{color_id}` | GET: 色別`filament`、共通`settings`、所属`product_id`。 |
| `/api/printers/{id}/ams` | GET: `printer_id`、`current`、`slots`、`auto_refill`。 |
| `/api/printers/{id}/ams/{slot_id}` | PUT: 観測revisionを指定して色を対応づけ、204。 |
| `/api/printers/{id}/ams/resolve?filament_id=...` | GET: 現在使用可能な同一材料の`candidates`と`preferred_slot`。候補なしは空配列/null、未同期は409。 |
| `/api/printers/{id}/ams/priority` | PUT: 同一材料グループ全体の使用順を更新、204。 |
| `/api/printers/{id}/ams/auto-refill` | PUT: `{"enabled":true}`で機器の設定を要求、202と`{"status":"requested"}`。反映はGETで確認。 |

製品の作成・共通情報更新:

```json
{"name":"Example PETG","vendor":"Example","material":"PETG","bambu_filament_id":null}
```

色の追加・更新:

```json
{"name":"白","color":"FFFFFFFF"}
```

返された色IDをAMSとキューの`filament_id`として使います。製品IDとは区別してください。
共通設定があれば、新しい色も追加直後から使用できます。
従来の`POST /api/filaments`は単色の製品を作成します。色IDを使うPUTと`/settings`操作も残していますが、
メーカー・種別・Bambu ID・機種別設定の更新は所属製品の全色へ反映されます。
新規の管理操作には製品APIを使ってください。

機種別設定の作成・更新形式:

```json
{
  "machine_profile_key":"Bambu Lab P1S 0.4 nozzle",
  "base_profile_key":"Generic PETG",
  "overrides_json":{"nozzle_temperature_initial_layer":240,"nozzle_temperature":220}
}
```

`overrides_json`は上記ノズル2項目と`bed_temperature_initial_layer`、`bed_temperature`の4項目のみです。未指定項目は基本値を使います。任意のG-codeや設定キーは受け付けません。
取得した設定の`resolved`は基本値と差分を解決した温度・要求硬度です。
基本プロファイルが利用できない場合は`resolved: null`と`error`を返します。

AMSスロットの識別項目は`id`、`printer_id`、`ams_id`、`slot_index`、`revision`です。
対応情報は`filament_id`、`mapping_source`、`filament`、`setting`です。
観測情報は`reported`、自動識別フラグ、`current`です。
`mapping_source`は`automatic`、`manual`、`unassigned`です。`filament_id: null`の手動解除もあります。
`reported`は機器の観測値で、`last_seen_at`はUnix秒です。`current: false`なら現在値として使用しないでください。
従来AMSの在席ビットで判定できないAMS IDの在席は未確認のまま保持します。

対応づけは`{"revision":1,"filament_id":"取得した材料ID"}`、解除は`filament_id: null`です。
観測が変わった・未同期・空スロットへの指定・参照中の削除・重複する機種別設定は409になります。
未知のIDは404、設定内容の不整合は400、不正なJSONの型・未許可キーは422、保存先やprofileの利用不可は503です。

優先順位の更新には`{"filament_id":"色ID","order":[{"id":"スロットID","revision":2},...]}`を送ります。
`order`は現在の同一材料グループを省略・重複なく全件指定します。各slotの`priority_group`が現在の順序とrevisionを返します。
観測や順序が変わった要求は409で拒否し、部分更新しません。製品または正確なRGBAが違う候補は混ぜません。
共通設定のない機種は解決できません。候補の選択時点で最新の状態を読み、印刷開始時も既存の条件を確認してください。

`load_order`は観測した装填世代、`priority_order`は保存した使用順です。日時・残量ではありません。
`auto_refill.supported`と`enabled`は報告された真偽値またはnull、`groups`は機器が認識した補充グループのbitmask配列またはnullです。
slotの`backup_peers`は機器が報告した補充候補の物理tray番号で、nullは未報告、空配列は候補なしです。
`current: false`の報告は現在値として扱わないでください。設定要求は同じTLS MQTT接続から一度だけ送り、再接続時に再送しません。

## 保存と移行

`<PLATES_DIR>/orca.sqlite3`のschema versionは6です。
`filament_products`が製品の共通情報、`filaments`が色と製品への参照、`filament_settings`が製品の機種別設定を持ちます。
`(product_id, machine_profile_key)`は一意です。`ams_slots`の`(printer_id, ams_id, slot_index)`も一意です。

旧DBは起動時の一つのtransactionで移行します。製品名・メーカー・種別・Bambu IDと全機種の基本設定・温度差分が
一致する色だけをまとめます。異なる個別調整や名前は別製品として残し、近い名前や色から推測しません。
既存の材料ID・AMS割当・待機/実行中ジョブ・固定入力は保持します。統合した設定IDは製品詳細から取り直してください。
移行で印刷開始を送信しません。不正な旧設定や参照の欠落があれば移行を取り消して起動を拒否します。
AMSの装填順と使用順も同じDBに保存し、旧版からの移行ではスロット番号順に初期化します。
台帳を観測値で上書きせず、受信した完全・差分報告からAMSの観測情報だけを更新します。

更新前にサーバーを停止して保存領域全体をバックアップしてください。
旧版へ戻す場合は、旧版のイメージと更新前の保存領域を組にして復元します。
DBにはプリンターのアクセスコードも含むため、バックアップを公開しないでください。
