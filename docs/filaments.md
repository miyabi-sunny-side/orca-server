# フィラメントとAMSの材料管理

使用するフィラメントを銘柄・色ごとに登録し、AMSの各スロットに対応づけます。
登録した材料と温度設定はSQLiteに保存されます。初期状態の台帳は空です。

## 材料を登録する

1. 右上のメニューから「フィラメント」→「追加」を開きます。
2. 名前、メーカー・銘柄、材料種別、8桁のRGBA色を入力して保存します。
3. 純正Bambu材料を自動識別する場合だけ、材料IDも入力します。PLA MatteのIDは`GFA01`です。
4. 材料の編集画面から「設定を追加」を選び、機種・ノズル径と基本プロファイルを指定します。

色はRRGGBBAAです。黒は`000000FF`、白は`FFFFFFFF`で、末尾`FF`は不透明を表します。
PETGとPETG-GFは別の材料として登録します。材料IDが同じでも、色の違う製品は別々に登録してください。
同じID・種別・色の候補が複数ある場合は、自動で一つを選びません。

## 機種別の温度設定

基本プロファイルは、同梱OrcaSlicer 2.4.2でその機種・ノズル径に対応するものから選択します。
初層と通常層のノズル温度は個別に上書きでき、空欄なら基本値を使います。
同じ材料・機種構成の設定は一つで、同じ構成の複数プリンターで共有します。
設定を変更しても、AMSが報告する温度範囲や材料名は書き換えません。

入力範囲は120〜350℃の整数です。これはアプリの入力制限で、機器がその全範囲に対応する保証ではありません。
材料メーカーの推奨温度と機器の上限を確認してください。
繊維入り材料は同種の樹脂の基本プロファイルも選べますが、ノズル適合は別に確認します。
0.2mm用の設定がなければ、0.4mm用の設定を流用しません。

印刷準備を開始すると、台帳の基本プロファイルと温度の上書きを固定してスライスへ適用します。
設定変更は次の準備から反映します。既に印刷中のデータは変更しません。
[スライスの設定](slicing.md)を参照してください。

## AMSに対応づける

「プリンター」一覧の「AMSの材料」を開きます。プリンター内のAMS IDとスロット番号ごとに表示します。
画面のスロット番号は1始まり、APIの`slot_index`は0始まりです。

- 自動対応: 装填・タグ・材料ID・種別・色が分かり、台帳の候補が一つの場合です。
- 手動対応: 「材料を指定・解除」で台帳の材料を選び、「対応を保存」を押します。
- 対応解除: 選択欄で「対応を解除」を保存します。同じ報告値のままなら、自動対応へ戻しません。

タグや報告値の変更、抜去を確認すると、それまでの対応を見直します。
残量だけが変わった場合は、手動対応を維持します。
タグのない材料を同じ報告値の別製品へ交換した場合は自動判別できないため、材料を指定し直してください。
編集中に観測内容が変わった場合は、画面を更新して選び直します。

「プリンターからの報告」には銘柄、色、材料ID、タグ、残量、温度範囲、自動識別設定を表示します。
残量`-1`などの未知値を0%として扱いません。起動直後・通信断・古い情報は「未確認」と表示し、
完全な状態報告を受け取るまで新しい材料の指定を受け付けません。古い対応の解除は可能です。
「状態を更新」はサーバーが受信した情報を読み直す操作で、RFID再読取・送り・加熱は起動しません。

ノズル適合表示は、登録した径・材質と基本プロファイルの要求硬度に基づきます。
実際の装着状態を保証する表示ではありません。未確認の材質・硬度は適合扱いにしません。
CF/GF入り材料の0.2mmは非対応、ステンレスは非対応とし、0.4mm焼入れ鋼は未確認とします。
[Bambuのノズル別材料条件](https://us.store.bambulab.com/products/bambu-hotend-p1-series)と材料メーカーの適合条件も確認してください。

AMSや印刷ジョブから参照される材料は削除できません。先に対応を解除し、ジョブを終了・取消します。
材料削除時は機種別設定も削除します。ジョブから参照される機種別設定の削除も拒否します。

## API

JSONを送る操作には`Content-Type: application/json`を付けます。IDは各APIの応答から取得します。

| URL | 操作 |
| --- | --- |
| `/api/filaments` | GET: 材料一覧。POST: 材料作成、201と作成結果。 |
| `/api/filaments/{id}` | GET: `filament`と`settings`。PUT: 材料更新。DELETE: 削除、204。 |
| `/api/filaments/{id}/profiles?machine=...` | GET: URLエンコードした機種キーに対応する基本プロファイルと温度。 |
| `/api/filaments/{id}/settings` | POST: 機種別設定の作成、201。 |
| `/api/filaments/{id}/settings/{setting_id}` | PUT: 機種別設定の更新。DELETE: 削除、204。 |
| `/api/printers/{id}/ams` | GET: `printer_id`、`current`、`slots`。 |
| `/api/printers/{id}/ams/{slot_id}` | PUT: 観測revisionを指定して材料を対応づけ、204。 |

材料の作成・更新形式:

```json
{"name":"Example PETG","vendor":"Example","material":"PETG","color":"FFFFFFFF","bambu_filament_id":null}
```

機種別設定の作成・更新形式:

```json
{
  "machine_profile_key":"Bambu Lab P1S 0.4 nozzle",
  "base_profile_key":"Generic PETG",
  "overrides_json":{"nozzle_temperature_initial_layer":240,"nozzle_temperature":220}
}
```

`overrides_json`はこの2項目のみです。未指定項目は基本値を使います。任意のG-codeや設定キーは受け付けません。
取得した設定の`resolved`は基本値と差分を解決した温度・要求硬度です。
基本プロファイルが利用できない場合は`resolved: null`と`error`を返します。

AMSスロットの識別項目は`id`、`printer_id`、`ams_id`、`slot_index`、`revision`です。
対応情報は`filament_id`、`mapping_source`、`filament`、`setting`、`nozzle_fit`です。
観測情報は`reported`、自動識別フラグ、`current`です。
`mapping_source`は`automatic`、`manual`、`unassigned`です。`filament_id: null`の手動解除もあります。
`reported`は機器の観測値で、`last_seen_at`はUnix秒です。`current: false`なら現在値として使用しないでください。
従来AMSの在席ビットで判定できないAMS IDの在席は未確認のまま保持します。

対応づけは`{"revision":1,"filament_id":"取得した材料ID"}`、解除は`filament_id: null`です。
観測が変わった・未同期・空スロットへの指定・参照中の削除・重複する機種別設定は409になります。
未知のIDは404、設定内容の不整合は400、不正なJSONの型・未許可キーは422、保存先やprofileの利用不可は503です。

## 保存と移行

`<PLATES_DIR>/orca.sqlite3`のschema versionは3です。
材料管理には`filaments`、`filament_settings`、`ams_slots`を使用します。
`ams_slots`の組`(printer_id, ams_id, slot_index)`は一意です。
機種別設定の組`(filament_id, machine_profile_key)`も一意です。
旧versionからの起動時移行は一つのtransactionで行い、既存プリンターを保持します。
台帳を観測値で上書きせず、受信した完全・差分報告からAMSの観測情報だけを更新します。

更新前にサーバーを停止して保存領域全体をバックアップしてください。
旧版へ戻す場合は、旧版のイメージと更新前の保存領域を組にして復元します。
DBにはプリンターのアクセスコードも含むため、バックアップを公開しないでください。
